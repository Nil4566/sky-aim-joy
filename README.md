# ✨ Sky Aim — ล่าดาวด้วยพิกัดทรงกลม (มือถือเป็นจอย)

ผู้เล่นยืนอยู่ที่จุดกำเนิดใต้ท้องฟ้ายามค่ำคืนแบบ 3 มิติ (Three.js) มีดาวที่มองไม่เห็นซ่อนอยู่ในทิศที่โจทย์บอกเป็นพิกัด
ผู้เล่น **เอียงมือถือ** เพื่อหมุนกล้องบนจอ Host แล้ว **ค้างเป้าเล็งไว้ที่ดาว 1 วินาที** เพื่อ “ค้นพบดาว”

เนื้อหาคณิตศาสตร์: การแปลงระหว่างพิกัดทรงกลม (r, θ, φ) กับพิกัดฉาก (x, y, z)

```
x = r sin φ cos θ        r = √(x² + y² + z²)
y = r sin φ sin θ        θ = atan2(y, x)      (วัดบนระนาบ xy จากแกน +x)
z = r cos φ              φ = arccos(z / r)    (วัดจากแกน +z ลงมา)
```

## โครงสร้างไฟล์

| ไฟล์ | หน้าที่ |
|---|---|
| `server.js` | Express (เสิร์ฟ `/public`) + Socket.IO — ทำหน้าที่ระบบห้องและ **ส่งต่อข้อมูลอย่างเดียว** |
| `public/index.html` | หน้าแรก มีปุ่มใหญ่ “จอ Host” และ “จอย (Client)” |
| `public/host.html` | ฉาก Three.js, ตัวสร้างโจทย์ 3 ด่าน, ระบบคะแนน, HUD, ล็อบบี้ + QR code |
| `public/client.html` | จอยบนมือถือ: เซนเซอร์เอียง, ทัชแพดสำรอง, ปุ่มต่างๆ |
| `public/style.css` | สไตล์ที่ใช้ร่วมกัน |

## วิธีรันในเครื่อง

ต้องมี Node.js 18 ขึ้นไป

```bash
npm install
```

```bash
npm start
```

แล้วเปิด <http://localhost:3000> (เปลี่ยนพอร์ตได้ด้วยตัวแปร `PORT`)

ทดสอบบนคอมเครื่องเดียวได้: เปิด **จอ Host** ในแท็บหนึ่ง และ **จอย (Client)** อีกแท็บ แล้วกรอกรหัสห้อง
ฝั่งจอยบนคอมไม่มีเซนเซอร์ ให้ใช้ **ทัชแพด** (ลากด้วยเมาส์/นิ้ว) แทน หรือควบคุมที่จอ Host ด้วยการลากเมาส์และปุ่มลูกศรก็ได้

> ⚠️ มือถือเปิด `localhost` ของคอมไม่ได้ และถ้าเปิดผ่าน IP วงแลน เช่น `http://192.168.1.10:3000`
> ก็จะเข้าห้องได้แต่ **อ่านเซนเซอร์ไม่ได้** เพราะไม่ใช่ HTTPS (ดูหัวข้อด้านล่าง) — ใช้ URL ที่ deploy แล้วจะสะดวกที่สุด

## Deploy บน Render ทีละขั้น

1. อัปโหลดโปรเจกต์นี้ขึ้น GitHub (ไม่ต้องอัปโหลดโฟลเดอร์ `node_modules`)
2. ไปที่ <https://render.com> แล้วสมัคร/ล็อกอิน (ล็อกอินด้วย GitHub ได้)
3. กด **New +** → **Web Service**
4. เลือก **Build and deploy from a Git repository** แล้วเชื่อมต่อกับ repo ของโปรเจกต์นี้
5. ตั้งค่า
   - **Runtime / Language:** `Node`
   - **Build Command:** `npm install`
   - **Start Command:** `npm start`
   - **Instance Type:** `Free` ก็พอ
6. กด **Create Web Service** แล้วรอจน log ขึ้นว่า `Sky Aim server กำลังทำงานที่ ...` และสถานะเป็น **Live**
7. จะได้ URL แบบ `https://ชื่อบริการ.onrender.com` — เปิด URL นี้บนคอม/โปรเจกเตอร์แล้วกด **จอ Host**
   มือถือสแกน QR code บนจอได้เลย (QR ชี้ไปที่ `https://.../client.html?room=รหัส`)

หมายเหตุ
- Render ตั้งค่า `PORT` ให้เอง server อ่านจาก `process.env.PORT` อยู่แล้ว และรองรับ WebSocket โดยไม่ต้องตั้งค่าเพิ่ม
- แพ็กเกจฟรีจะ “หลับ” เมื่อไม่มีคนใช้ราว 15 นาที การเปิดครั้งแรกหลังจากนั้นอาจรอ 30–60 วินาที
- ทุกครั้งที่ push ขึ้น GitHub, Render จะ deploy ใหม่ให้อัตโนมัติ

## ทำไมมือถือต้องใช้ HTTPS เพื่ออ่านเซนเซอร์

- เบราว์เซอร์สมัยใหม่ถือว่าข้อมูลการเคลื่อนไหว (`devicemotion`) เป็นข้อมูลอ่อนไหว — อาจใช้เดาสิ่งที่พิมพ์บนจอหรือติดตามตัวผู้ใช้ได้
  จึงอนุญาตให้ใช้เฉพาะใน **secure context** คือหน้าที่เปิดผ่าน `https://` (หรือ `localhost` บนเครื่องตัวเอง)
- Chrome บน Android: ถ้าเปิดผ่าน `http://` จะไม่ส่งเหตุการณ์ `devicemotion` มาเลย
- Safari บน iOS 13+: ต้องเรียก `DeviceMotionEvent.requestPermission()` **ภายในการกดปุ่มของผู้ใช้** เท่านั้น
  (จึงมีปุ่ม “เปิดใช้เซนเซอร์”) และฟังก์ชันนี้ใช้ได้เฉพาะบน HTTPS
- หน้าจอยจะแจ้งเป็นภาษาไทยถ้าผู้ใช้ไม่อนุญาต หรือไม่มีข้อมูลเซนเซอร์เข้ามาภายใน 1.5 วินาที แล้วให้ใช้ทัชแพดแทนได้
- Render ให้ HTTPS ฟรีอัตโนมัติ จึงเหมาะที่สุด (ถ้าจะทดสอบในวงแลนให้ใช้ tunnel ที่เป็น HTTPS เช่น cloudflared หรือ ngrok)

## วิธีเล่น

1. เปิด **จอ Host** บนคอม/โปรเจกเตอร์ จะเห็นรหัสห้อง 4 หลักตัวใหญ่ และ QR code
2. มือถือสแกน QR (รหัสห้องจะถูกเติมให้อัตโนมัติ) หรือเปิด **จอย (Client)** แล้วกรอกรหัส — เข้าได้หลายเครื่องต่อห้อง
3. กด **เปิดใช้เซนเซอร์** แล้วถือมือถือในท่าที่สบาย ระบบใช้ท่าแรกเป็นศูนย์ให้อัตโนมัติ (กด **ตั้งศูนย์** ใหม่ได้ตลอด)
4. กด **เริ่มเกม** (บนจอ Host หรือบนมือถือก็ได้)
5. การควบคุมเป็นแบบ **ควบคุมความเร็ว** — เอียงมากหมุนเร็ว เอียงน้อยหมุนช้า กลับมาท่าศูนย์ภาพจะหยุด จึงไม่ต้องหันหลังให้จอ
   - เอียงขวา → มุมมองหันขวา (θ ลดลง)
   - เอียงเครื่องเข้าหาตัว → มุมมองเงยขึ้น (φ ลดลง)
   - กดค้าง **เล็งละเอียด** → หมุนช้าลงเหลือ 25%
   - ถ้าทิศกลับด้าน ติ๊ก **สลับทิศแกน X / Y**
6. เล็งให้ดาวอยู่ในเป้า แล้วค้างไว้ 1 วินาที (วงแหวนรอบเป้าเล็งจะเต็ม) → ค้นพบดาว! มือถือจะสั่น
7. หลังเจอหรือข้ามแต่ละข้อ จะมี **วิธีทำ** แสดงขั้นตอนการแปลงพิกัด แล้วกด **ข้อต่อไป** (หรือรอ 15 วินาที)
   ดาวที่เจอแล้วจะค้างอยู่บนฟ้าและเชื่อมกันเป็น “กลุ่มดาว”

### ด่าน (ด่านละ 4 ข้อ)

| ด่าน | โจทย์ | ค่าที่แสดงบนจอ | ยอมคลาดเคลื่อน |
|---|---|---|---|
| 1 | ให้ (θ°, φ°) | (θ, φ) ของทิศที่เล็ง | 6° |
| 2 | ให้จุดจำนวนเต็ม P = (x, y, z) | (θ, φ) เท่านั้น → ต้องแปลงเองด้วย atan2 และ arccos | 7° |
| 3 | ให้ (r, θ, φ) เป็นเรเดียน เช่น (4, 5π/6, π/3) | (x, y, z) ของจุดที่ห่าง r ตามแนวเล็ง | 7° |

### คะแนน

- คะแนนต่อข้อ = **100 + โบนัสเวลา − ค่าปรับคำใบ้** (โบนัสเวลาเริ่มที่ 60 ลดลง 1 ต่อวินาที)
- **คำใบ้** (หัก 40 คะแนน): แสดงวงกระพริบที่ตำแหน่งดาว พร้อมระยะห่างเป็นองศา
- **ข้าม**: ได้ 0 คะแนน กล้องจะหมุนไปที่ดาวและเฉลยคำตอบ

### ปุ่มลัดบนจอ Host

ลากเมาส์ หรือ ← ↑ → ↓ (กด Shift = ละเอียด) · `H` คำใบ้ · `S` ข้าม · `Enter` เริ่ม/ข้อต่อไป · `F` แผงสูตร

## โปรโตคอล Socket.IO (สำหรับผู้พัฒนา)

| ทิศทาง | เหตุการณ์ | ข้อมูล |
|---|---|---|
| host → server | `host:create` | `{room?}` ขอใช้รหัสเดิมได้ถ้ายังว่าง → ตอบ `{ok, room}` |
| client → server | `client:join` | `{room}` → ตอบ `{ok}` หรือ `{ok:false, error}` |
| client → host | `tilt` | `{x, y, fine}` (volatile ~30 ครั้ง/วินาที; server เติม `id`) |
| client → host | `action` | `{name: 'start' \| 'hint' \| 'skip'}` |
| host → clients | `game` | `{type: 'lobby' \| 'target' \| 'hit' \| 'skip' \| 'end', ...}` — server จำ `lobby`/`target`/`end` ล่าสุดไว้ส่งให้มือถือที่เข้าทีหลัง |
| server → host | `clients` | `{count, ids}` ทุกครั้งที่จำนวนมือถือเปลี่ยน |
| server → clients | `host-left` | เมื่อ host หลุด (มือถือจะลองเข้าห้องเดิมใหม่ทุก 2 วินาที) |
